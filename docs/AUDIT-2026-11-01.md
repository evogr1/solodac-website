## Security

## Confirmed

**1. Medium: no security headers on any response.** Where: https://solodac.com/, /katran, /contact, /api/ticker. Every response has only content-type, cache-control and server. CSP, HSTS, X-Frame-Options or frame-ancestors, X-Content-Type-Options, Referrer-Policy and Permissions-Policy are all missing.
- Scenario: any site can load solodac.com in an iframe and clickjack the contact form. If an XSS ever lands, nothing limits it.
- Fix: in `worker/index.ts`, wrap `env.ASSETS.fetch` and add these headers to every response:
  - `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' https://fonts.googleapis.com 'unsafe-inline'; font-src https://fonts.gstatic.com; img-src 'self' data: https:; connect-src 'self' https://api.web3forms.com; frame-src https://www.youtube-nocookie.com; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`
  - `Strict-Transport-Security: max-age=31536000; includeSubDomains`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
  - Then check the effects and inline styles on the preview URL before going live. A `_headers` file is an alternative.

**2. Low: no spam protection on the contact form.** Where: `client/src/lib/web3forms.ts:1-8`, `LeadForm.tsx`. The form posts straight from the browser to api.web3forms.com. The access key `fa96ec00-...` is in the bundle. That is how Web3Forms is meant to work, since the key only routes mail to your inbox, so it is not a leaked secret. But there is no honeypot, captcha or field length limit, and the Worker never sees the request, so it cannot rate-limit.
- Scenario: a bot replays the request in a loop. The info@ inbox floods and the Web3Forms monthly quota runs out, so real leads stop arriving. Because `...fields` is spread after `access_key`, a direct caller can also set Web3Forms control fields such as `subject` or `from_name`. They could do that with curl anyway, so it adds no new risk.
- Fix: add Web3Forms' `botcheck` honeypot (a hidden checkbox) and enable their hCaptcha. Add `maxLength` to inputs (for example 200, and 5000 for the textarea). In the Web3Forms dashboard, limit the key to the solodac.com domain if your plan allows it. Header and email injection is handled by Web3Forms, not by this code.

**3. Low: www.solodac.com returns Cloudflare 522.** It is reachable over HTTPS, but there is no origin behind it. Visitors who type www get an error page. Fix: add a Worker route or a redirect rule from www to the apex domain.

**4. Info: the Manus debug collector is deployed but not loaded.** Where: `client/public/__manus__/debug-collector.js`, live at https://solodac.com/__manus__/debug-collector.js (HTTP 200). It is a Manus AI-builder dev script that records console output, network requests and keystrokes, then posts them to `/__manus__/logs`. `vite.config.ts:82` injects it only when not in production, and the live HTML does not load it. In production nothing collects data and there is no `/logs` endpoint. It is dead weight that leaks tooling details. Fix: delete `client/public/__manus__/`, `ManusDialog.tsx` and `client/src/const.ts` (unused OAuth leftovers). Also drop the Manus plugins and `allowedHosts` from `vite.config.ts`.

**5. Info: the dependency audit is noisy, but none of it ships.** `pnpm audit --prod` reports 85 issues: 1 critical (proxy-addr) and 20 high (axios, express, path-to-regexp, body-parser, lodash, dompurify, zod, nanoid, form-data). The full audit reports 167 (5 critical, all dev tooling: vitest, tinypool, tar). None of these packages is imported by `client/src`, `shared` or `worker`, and the built bundle contains none of them. Express only serves `server/index.ts`, which Cloudflare does not run. Fix (hygiene): remove unused template dependencies (axios, express, streamdown, recharts, zod, nanoid, unused Radix packages) so the audit means something again.

## Checked and fine

- **`/api/ticker`** (`worker/index.ts`, `shared/ticker.ts`): no user input, fixed symbol list, and a fixed cache key that ignores the query string. There is no SSRF and no cache-busting. It fails closed to `[]` and leaks no errors. Small note: when Yahoo fails, nothing is cached, so each hit sends 15 subrequests. Caching the empty result for about 30s would fix that.
- **CORS:** no CORS headers, which is the right default. Unknown `/api/*` paths fall through to the SPA.
- **Secrets:** a grep of the working tree and all 117 commits found no private keys, cloud or GitHub tokens, or `.env` files. `.env` is gitignored. The Maps or Forge keys in history are read from `import.meta.env`, never written in literally. The only literal is the Web3Forms public key.
- **`?service=` on /contact** (`Contact.tsx:8-9`): it is checked against `serviceOptions` and only used as a select value. No injection and no open redirect. No other code reads the URL.
- **DOM sinks:** the only `dangerouslySetInnerHTML` is in the shadcn `ui/chart.tsx`, which nothing imports. There is no `innerHTML` or `eval`.
- **`target=_blank`:** all three links have `noreferrer`, which implies `noopener`. YouTube embeds use youtube-nocookie.com.
- **Third-party scripts:** none. Only Google Fonts CSS is loaded. There are no analytics. The bundle is first-party, so SRI is not needed.
- **No source maps** are published.

## Worth checking (could not confirm from here)

- **HTTP to HTTPS redirect:** through this sandbox's proxy, `http://solodac.com/` returned 200, not a redirect. Turn on "Always Use HTTPS" in Cloudflare and confirm it from a normal network. HSTS (item 1) covers repeat visits.
- **Public previews:** every pushed branch gets a public `*.workers.dev` URL. That is fine while branches hold no secrets, but draft content is public. If that matters, add Cloudflare Access to `*.workers.dev`.

## Design, UX, accessibility and motion


**Verdict.** The site is cleaner than earlier passes and the copy mostly follows the rules (no em-dashes found anywhere in client/src). It still reads as templated, because every section uses the same move: a white sentence, then a grey second sentence, over an orange mesh glow. Accessibility has real gaps: Reveal ignores reduced motion, the tabs have no arrow keys, the rotating word cannot be paused and several greys fail contrast. About 50 files are dead code.

Screenshots were taken at 1440 and 390 and checked by eye (marked [seen]). They are in `/tmp/claude-0/-home-user-solodac-website/8295f574-1c6d-55a1-84a9-6a05fdcbacf7/scratchpad/design-audit/`.

## Slop and visual

1. **The two-tone headline on every section.** [seen] Home.tsx:85,107,149,173,221; Services.tsx:14; Network.tsx:81; About.tsx:182; Katran.tsx:68. Nine headings follow "Statement. *grey follow-up.*". Repeated this often, it reads as a generated template, and in the hero the grey part is the rotating word, the one thing that changes. Fix: keep it in one or two places at most. Make the hero word full paper or signal, and let the other headings be a single plain sentence.
2. **The orange mesh glow on the hero, Services and Contact.** [seen] Home.tsx:76, Services.tsx:13, Contact.tsx:14. This is the stock dark-mode AI hero look. Fix: keep it on Home only, or replace it with real work: a strip of reels or channel thumbnails.
3. **The "Everything we do" word cloud.** [seen] Home.tsx:130-137. Nineteen items alternate white and paper/40. The pattern is decorative and makes no list easy to scan. Fix: group the items under the six services as a short list that links to /services#id, or cut the section. The picker and /services already cover this.
4. **YouTube, editing, identity and websites have no visual proof.** [seen] Services.tsx:26-52 shows six zebra blocks of text and checklists, with no thumbnails or sites. GrowthPicker.tsx:383 proves "YouTube channels" with a Shorts reel. GrowthPicker.tsx:419 shows the word "Katran" in a box built for a number. The site still looks reels-first. Fix: add one real long-form thumbnail with its view count for YouTube, a before and after edit for Editing, and a site or logo shot for Identity. Use them on /services and in the picker.
5. **The Katran block on Home is mostly empty space, and its headline is used twice.** [seen] Home.tsx:217-230 repeats the Katran.tsx:66-69 h1 word for word. Fix: show one reel or the tool list here, with different words.
6. **The spider on Network.** [seen] CrawlerSpider.tsx sits over the card titles (1440 and 390) and tints cards orange-brown (index.css:204), so they look selected. On a page that sells brand deals it is a gimmick that hides the data. Fix: remove it, or run it only after hover and keep it off the text.
7. **The globe is cropped.** [seen] Network.tsx:79: at 1440 it is cut off at the right edge and shows partial words. Fix: keep it inside the container.
8. **The particle word on About.** [seen] About.tsx:186-190 uses a 420px band to spell the logo. It is filler. Fix: cut it, or put a team or office photo there.
9. **The final CTA blends into the footer.** [seen] Both use bg-ink-2 (Home.tsx:267, Layout.tsx:274), so they read as one block. Fix: give the CTA ink or paper.

## UX and copy

1. **On mobile, the comparison table hides the SoloDac column.** [seen] Home.tsx:176-177 sets min-w-[720px], so at 390 the column the table exists for is off-screen. Fix: on small screens show stacked rows with a "SoloDac vs others" layout, or pin the last column.
2. **Claims nobody can check.** These are not sourced: "A typical agency: Some/Rarely" (Home.tsx:45-49); "For less than one editor's salary" with no price (Home.tsx:221, Katran.tsx:28,68); "unbranded pages... US, UK" (Home.tsx:66, Network.tsx:120); "millions of people watch" (Layout.tsx:279); "checks the facts" (Katran.tsx:20). Fix: back each one with a number or link, or soften it.
3. **The same lines repeat across pages.** "We only take partnerships that fit the page" appears 3 times (site.ts:183, Home.tsx:65, Network.tsx:132). "honestly what we'd do" appears twice (Home.tsx:68,274). "Under one roof" appears on Home.tsx:127 and Services.tsx:14. Fix: keep one of each.
4. **"No slop" as a value** (About.tsx:165). It is jargon and invites the exact judgement the owner is trying to avoid. Fix: "Nothing looks machine-made."
5. **Every page has the same `<title>`** (index.html:16, and nothing sets document.title). This hurts SEO and makes tabs hard to tell apart. Fix: set a title per route.
6. **The GrowthPicker panel changes height when you switch tabs**, and on mobile the full-width reel makes the panel about 1.5 screens tall [seen 390]. Fix: cap the proof at about 200px on mobile and fix the panel's min-height.
7. **LeadForm.** Selects have appearance-none and no chevron [seen 390], so they look like text fields (LeadForm.tsx:130). The error message (line 168) is not in a live region, and focus is lost when the success panel replaces the form. Fix: add a chevron, put the error in `role="alert"`, and move focus to the success heading.
8. **Break-ui findings.** `totalFollowersInThousands` (site.ts:230) ignores an "M" suffix, so "1.2M" would count as 1.2. `totalReelViews` (Home.tsx:17) shows "0 crore" below 1 crore. The `!` lookups in GrowthPicker.tsx:360-361 crash the home page if a reel id is renamed. Network card names are 3xl with no wrapping guard, and a missing logo shows a broken image. Fix: parse K and M, use a lakh fallback, and add guarded lookups and a logo fallback.

## Accessibility

1. **Reveal and the page transition ignore reduced motion.** Reveal.tsx:127-133 and App.tsx:222-227 have no `useReducedMotion` and no `<MotionConfig reducedMotion="user">`. Framer's JS transforms are not covered by the CSS kill in index.css:134. Fix: wrap App in MotionConfig with reducedMotion="user".
2. **Contrast failures.** Measured on ink: paper/45 = 4.13, /40 = 3.48, /35 = 2.92. ink/40 on paper = 2.65. These fail at small sizes: footer labels and roles (Layout.tsx:287,303,320), @handle (Network.tsx:102), the GSTIN and city roles on Contact (Contact.tsx:34,39), "No" cells in the table (Home.tsx:202), and inactive desktop tabs at /35 (GrowthPicker.tsx:448). paper/55 and above pass. Fix: set a floor of /55 for body-size text and /45 for 24px+ text.
3. **GrowthPicker tabs** (GrowthPicker.tsx:436-453). There is no arrow-key, Home or End support and no roving tabindex, so all five tabs are tab stops. Fix: add the standard ARIA tabs keyboard model.
4. **The rotating hero word** (RotatingWord.tsx:506-521) loops forever with no pause, which fails WCAG 2.2.2. Fix: stop after one cycle on the last word, or pause it on hover and focus.
5. **Mobile menu** (Layout.tsx:251-265). Escape does not close it, it has no focus trap, and focus does not return to the toggle. Fix: add all three.
6. Heading order is fine. Alt text is fine: posters are decorative and the buttons are labelled. Focus rings exist (index.css:74).

## Motion and performance

1. **Route changes wait about 700ms** (App.tsx:221, mode="wait", 350ms exit plus 350ms enter) on every click. The fixed header sits inside the transformed div, so it also fades and shifts. Fix: drop the exit, use a 200ms opacity-only enter, and move Header and Footer outside the animated wrapper.
2. **GrowthPicker uses mode="wait"** (line 458), so a tab click takes 600ms to show content and fast clicks queue up. Fix: crossfade with mode="popLayout", or switch instantly with a 150ms fade.
3. **FiveHires animates `gap`, `borderRadius` and colour** (FiveHires.tsx:320-338). These are layout and paint properties with a 0.5s delay. Fix: use transforms (translateX the chips together) or accept it, because it runs once.
4. **Magnetic reads getBoundingClientRect on every pointermove**, from 3 instances, and measures its own translated box, so the pull chases itself (Magnetic.tsx:141-146). Its `will-change-transform` is on permanently. Fix: measure on enter or resize only, and drop will-change.
5. **MeshGradient allocates new arrays and objects every frame** (MeshGradient.tsx:103-104). The spider calls getBoundingClientRect twice per frame (CrawlerSpider.tsx:133-134). Fix: mutate in place and cache the rects on resize.
6. **The hero letters animate `filter: blur`** for each letter (index.css:167). This is acceptable once, but drop the blur on mobile.
7. **Good:** effects pause off-screen and when the tab is hidden, and the cursor effects check for a fine pointer.
